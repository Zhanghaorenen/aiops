# 内存资源保护

服务器详情页新增「内存资源保护」，模式为关闭、仅观察、自动处置。范围按管理员声明的业务账号UID授权，不要求每个训练任务单独标记可抢占；与采集端本地允许UID取交集。默认关闭，不会因升级而自动结束进程。

## 行为

采集端每2秒检查本机Available RAM和memory PSI，独立于指标上报与LLM网络请求。可用内存低于配置的MiB水位或总量百分比水位，并有PSI压力，持续达到设定时间后评估；PSI不可用时，只有可用内存低于256MiB或总量0.5%的极低水位才评估。CPU高、GPU利用率高、显存接近满或Swap占用高，均不会单独触发结束进程。

符合权限和保护规则的业务进程中，选择RSS最高且超过最小RSS门槛的一项；这表示较大的内存占用贡献者，不是LLM已确认的故障根因。每轮只处理一个PID，不扩散到进程树或整个进程组。

先写入并fsync本地PREPARED审计，再通过Linux pidfd发送SIGTERM。等待退出宽限期后，再次核验授权、身份、保护状态和实际内存压力；仍符合条件才用同一pidfd发送SIGKILL。资源恢复、策略关闭、本地停止或身份改变时取消升级。没有pidfd支持时不使用裸PID强杀后备。结果区分已退出、已发信号但未确认、取消、权限/执行失败；不会把请求受理当作处置成功。

默认持续10秒、两次尝试间隔60秒、每小时最多3次。冷却和小时熔断把尝试计入预算，重启后从持久审计恢复，避免重启清空限额。观察/无可处置目标事件最多每30秒一条；本机日志约1MiB轮转，保留当前与上一份。上传使用幂等事件UUID，平台展示最近50条。

单次候选扫描最多4096个进程，只保留当前最大RSS候选，不在内存紧张时堆积完整进程快照。扫描被截断时状态会注明；它不是对全机进程根因的完整证明。同一状态目录使用Linux文件锁限制单个守护器。缓存策略绑定采集凭据摘要，凭据改变后必须重新同步授权；历史尝试仍计入熔断预算。

## 排除与权限

- root与UID<1000不在业务范围；PID 1、采集器及其祖先进程不处置。
- system.slice中的进程、systemd服务单元及与采集器相同单元内的进程排除。
- SSH、systemd、数据库、容器运行时、Java/Node平台进程，以及识别到的aiops_agent、uvicorn、gunicorn、Daphne、Celery等平台入口排除。
- 自定义平台服务应使用独立服务账号/systemd单元，或加入本机保护PID清单。不要把未识别的自定义平台与业务进程混在同一业务UID范围；无法可靠识别服务/cgroup时不处置。保守排除也可能保护一些Java/Node或systemd方式启动的业务任务。
- `PID + create_time + UID`绑定身份，并使用pidfd防止PID复用。权限不足不会提升权限、调用sudo、SSH或shell。
- 只有工作空间ADMIN可写策略或请求检查；VIEWER/OPERATOR可按已有节点查看权限读取状态。采集凭据仅同步自身节点，不能配置策略；用户JWT不能冒充采集凭据。

## LLM工具

`get_resource_guard_status(server_id)`读取策略、采集端状态和审计。

`request_resource_relief(server_id)`仅管理员可请求一次保护检查，30秒限流、请求有效期60秒。没有PID、信号或命令参数；不能启用策略或绕过本地阈值。返回`requested=true, executed=false`只是排队，须查看实际审计判断后续结果。自动保护不等待模型推理；LLM只负责查证、请求检查及解释。

## 部署与启用

本次实现没有修改真实服务器配置，没有在真实训练进程上发送信号。先升级Java/FastAPI和采集代码，备份数据库后让Flyway应用V15（只新增策略/事件表，不修改现有业务表）。前端构建后可在服务器详情页配置。

Linux需支持`os.pidfd_open`和`signal.pidfd_send_signal`。采集端已有systemd用户服务的环境文件中加入：

```dotenv
AIOPS_RESOURCE_GUARD=1
AIOPS_GUARD_ARMED=0
AIOPS_GUARD_BUSINESS_UIDS=1001
# 可选：自定义平台服务PID，仅为保护清单，不是待结束进程
AIOPS_GUARD_PROTECTED_PIDS=
```

1001仅为配置示例，必须替换为实际业务账号UID。推荐先以`ARMED=0`和网页「仅观察」核对候选是否全部属于业务范围；确认后由管理员将本地开关设为`ARMED=1`，并在网页选择「自动处置」。只有本地开关、平台AUTO模式、双方业务UID交集和压力条件全部满足时才可能处置。远端API/LLM不能修改本地开关或扩大本地UID权限。

采集端上报保护状态后，页面会显示本地开关、UID范围、最后同步和真实处置事件。策略缓存最长有效5分钟：后端短暂不可用时仍可本地检查，超过5分钟停止自动动作，避免长期执行已无法确认的授权。进程终止需要对应Linux权限；建议用专用业务账号运行，保护器不自动取得root。

关闭：网页先保存「关闭」，等待采集端同步；紧急关闭可将本地ARMED设为0并重启采集服务。网络断开时网页关闭并非立即生效，最晚受5分钟租约限制；不要把未同步的策略当成已执行。

## 已验证与限制

验证涵盖规则、PID复用、保护进程、压力恢复、审计失败、冷却/熔断、TERM→KILL同一pidfd、JWT/Agent凭据隔离、管理权限、事件幂等及前端构建。终止信号在单元测试中使用替身；未制造真实OOM、未结束真实训练进程，也未进行Linux生产强杀验收。

无法保证所有OOM都可避免：极快的内存突增、保护器自身被OOM、内核/驱动卡死、不可中断睡眠、没有可处置业务目标、冷却熔断或权限不足都可能阻止恢复。RSS含共享页，结束一项进程不保证释放等量物理内存。若要求强硬的单任务隔离，应另行给业务工作负载配置cgroup/container的memory.high/memory.max，不能仅依赖LLM或用户态守护器。本功能不修改GPU驱动、设备配置或系统OOM策略。
