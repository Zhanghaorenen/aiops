# 实验室双 GPU AIOps 演示指南

## 背景与结构

面向多人使用同一 Linux 双 GPU 服务器的实验室。平台监控、告警、辅助调查和使用登记；不提供硬件配额、实际任务调度或自动 Shell。

轻量 Agent → Spring Boot/MySQL（资产、权限、监控、告警、事件和任务）→ Vue。FastAPI 使用 LangGraph 调查流程和 LangChain 官方 RAG，Qdrant/本地 Embedding 提供文档证据，兼容 LLM 提供待验证假设。调查结果存回 MySQL，用户人工审核。

## 演示 A：共享 GPU 查询

1. ADMIN 添加 OPERATOR 与 VIEWER，两者看到相同授权服务器。
2. 三个用户分别查看 GPU 编号/UUID/显存/进程；管理员演示其他角色无法签发注册 Token。
3. 提问“哪张 GPU 更适合新任务”，核对工具调用、采样时间和只读建议。
4. 在 GPU 使用登记中添加计划，明确登记不会预留资源，和实际进程分开展示。

## 演示 B：CUDA OOM

1. 上传真实运维资料，确认 READY 与页码原文。
2. 询问“显存看似充足但 CUDA OOM 应检查什么”。
3. 核对 GPU/进程工具、知识检索来源以及证据不足提示。
4. 展示引用只来自实际返回片段，来源文档保持私人权限。

## 演示 C：异常 → 调查 → 人工审核

1. 配置温度或 CPU 规则。真实演示使用实际采样；如使用测试数据，必须在场景和记录中明确标为模拟，不混写生产指标。
2. 观察持续异常触发、去重、人工确认与真实恢复的区别。
3. 创建 Incident 关联告警，点击 AI 调查，查看任务状态、原始采样、假设、反证/缺失信息、来源和建议。
4. 人工标记报告是否有帮助；确认系统未实际操作服务器。

## 技术难点与可讲解内容

- JWT 身份与数据库成员权限分离，防角色缓存导致撤权延迟；Token 与 Agent Credential 分离。
- 规则行锁加唯一活动 key，避免多实例/并发重复告警；最后 ADMIN 变更锁同一工作空间。
- 微秒 UTC 时间解释、样本新鲜度/持续窗口/间隔、恢复阈值和冷却。
- 数据库任务租约、幂等请求、独立 Worker 线程池和失败恢复；不持久化 JWT。
- GPU index 非连续、UUID 保留、整机进程单次查询、缺测不补 0。
- 模型只提假设，证据编号与文档引用受校验；含私人 KB 的报告只对发起人可见。
